# CampusConnect — Student Management System

A modern Laravel student management portal for the Advanced Web Application Development (BUC3131) coursework. It includes authentication, role-based access, student and course CRUD, course registrations, relational Eloquent models, seed data, and responsive Blade pages.

## Features
- Secure login and logout through Laravel Breeze.
- Roles: **Administrator**, **Lecturer**, and **Student**, powered by `spatie/laravel-permission`.
- Administrator: create, view, edit, search and delete student/course records; view and remove registrations.
- Lecturer: view assigned courses and students registered in those courses.
- Student: browse available courses, register once per course, and view only their own registrations.
- Validated forms, flash success/error messages, capacity checks, database foreign keys, and unique student-course registrations.
- Seeders for five students, four courses, and sample role accounts.
- Responsive CampusConnect logo, sign-in page and dashboard.

## Requirements
- PHP 8.2+ (match the Laravel version installed)
- Composer
- MySQL or MariaDB
- Node.js and npm
- Git (recommended for the coursework collaboration requirement)

## Installation

1. Create a fresh Laravel project and install the required packages:

   ```bash
   composer create-project laravel/laravel student-management-system
   cd student-management-system
   composer require spatie/laravel-permission
   composer require laravel/breeze --dev
   php artisan breeze:install blade
   npm install
   ```

2. Copy/merge the files from this CampusConnect package into the Laravel project root. Keep Laravel's generated framework files and merge the supplied `app`, `database`, `resources`, `routes`, and `public` folders. The `routes/auth.php` file is generated by Breeze; retain it.

3. Create a MySQL database, for example `campusconnect`, then update `.env`:

   ```env
   APP_NAME=CampusConnect
   APP_URL=http://127.0.0.1:8000
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=campusconnect
   DB_USERNAME=root
   DB_PASSWORD=
   ```

4. Register Spatie middleware aliases for Laravel 11/12. In `bootstrap/app.php`, add the import near the top:

   ```php
   use Spatie\Permission\Middleware\RoleMiddleware;
   use Spatie\Permission\Middleware\PermissionMiddleware;
   use Spatie\Permission\Middleware\RoleOrPermissionMiddleware;
   ```

   Then inside the existing `->withMiddleware(function (Middleware $middleware) { ... })` callback, add:

   ```php
   $middleware->alias([
       'role' => RoleMiddleware::class,
       'permission' => PermissionMiddleware::class,
       'role_or_permission' => RoleOrPermissionMiddleware::class,
   ]);
   ```

5. Publish the Spatie permission migration, then migrate and seed:

   ```bash
   php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider"
   php artisan optimize:clear
   php artisan migrate:fresh --seed
   ```

   **Warning:** `migrate:fresh` drops all tables in the configured database. Use it only with a development database you are happy to reset. For a database with existing data, use `php artisan migrate --seed` instead.

6. Build frontend assets and start the app:

   ```bash
   npm run build
   php artisan serve
   ```

   Open `http://127.0.0.1:8000` in your browser.

## Important setup notes
- `User` uses Spatie's `HasRoles` trait. Keep the standard Breeze `routes/auth.php` and auth controllers/views, or use the supplied `resources/views/auth/login.blade.php` as your login view.
- Ensure the standard Laravel `users` table migration runs before the student/course migrations.
- If you change the role names, update the role seeder and route middleware consistently.
- Student self-registration in the demo expects the student's `users` account to be linked to a `students` record through `students.user_id`. The sample seeder creates this link.
- Student and course profile records are protected by role middleware; students only receive their own registration list.

## Database relationships
- `User hasOne Student` — account linked to a student profile.
- `User hasMany Course` — a lecturer may teach multiple courses.
- `Student hasMany CourseRegistration`; `Course hasMany CourseRegistration`.
- `Student belongsToMany Course` and `Course belongsToMany Student` through `course_registrations`.
- A unique composite index on `(student_id, course_id)` prevents duplicate registrations at database level.
